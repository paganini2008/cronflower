Distributed cron for the JVM, with a console.

cronflower is a distributed, stateful cron scheduler that forms its own cluster and needs no external database, broker, or coordinator. Drop @Task on a Spring bean and the cluster owns the schedule; declare a @Dag and it runs a whole workflow across your machines.

Get started on GitHub Read the docs
cronflower = cronsmith (distributed scheduling) + cronflow (DAG orchestration)

Everything a scheduler needs, nothing to provision

No separate database, message broker, or coordination service. Embedded store, self-forming cluster, self-balancing console.

◈

Self-clustering & HA

Nodes gossip and elect a leader among themselves — no ZooKeeper or etcd. The leader schedules and dispatches; followers fail over. No cron fires twice, none goes missing.

⛁

Stateful & durable

Schedules and execution history live in a store auto-detected from the JDBC URL: in-memory → H2/SQLite → MySQL/PostgreSQL. A restart or failover loses nothing.

⚡

Scales horizontally

A timing wheel drives large task volumes; group sharding spreads them across nodes and weighted dispatch fans runs out to executors by capacity.

⌗

Rich @Task model

Cron, year-based YCRON, fixed interval, or ISO-8601 duration — plus retry with back-off, per-run timeout, misfire policy, and repeat/stop-at limits, all declarative.

⤳

DAG orchestration

Declare a workflow of @Dag nodes with typed channels, branching, joins, subgraphs, and dynamic fan-out. The cluster drives the graph across executors.

▤

Operator console

Tasks, Executors, Cluster, DAG runs, System Health, and a live Settings view — one endpoint, UTC-first with a per-viewer time-zone toggle.

See the whole deployment at a glance

A web console talks to one endpoint and self-balances across every node, with automatic failover.

From clone to a live cluster in one command

Nothing to provision — the store is an embedded H2 file and the nodes elect a leader themselves. One command brings up a real distributed cluster with a web console.

Browse the repo

# clone and run — scheduler + console + 1 executor
git clone https://github.com/paganini2008/cronflower
cd cronflower/deploy
./run-local.sh -e 1

# open http://localhost:7200  (admin / admin123)
# scale into a cluster:
./run-local.sh -n 3 -e 2
